# SnakeRule 开发路线图

本文记录当前已实现能力、明确限制和仍需完成的工作。版本号以仓库根目录 `VERSION` 为准。

## 当前能力

- Go HTTP API 使用 `/api/v1`，返回统一 JSON 响应；OpenAPI 是管理端 API 契约，TypeScript SDK 由 `make gen-sdk` 生成。
- PostgreSQL 保存组织、用户、项目、凭据、规则集、发布快照、告警渠道、站内通知、会话和调用日志。新数据库从单一初始 schema 建表。
- 默认组织包含组织管理员登录名 `admin`，初始密码 `admin123`；超级管理员由 `AUTH_EMAIL`、`AUTH_PASSWORD` 配置。
- 项目支持 API Key、项目 JWT 和成员角色管理。
- 规则集支持草稿保存、发布为不可变快照、查看历史快照、并排查看版本及以新版本回滚。项目 API 仅执行已发布版本，设计器模拟可执行草稿。
- 调用日志持久化请求 ID、来源、规则集发布版本、命中状态、耗时及脱敏后的请求/响应预览；支持按规则集、请求 ID、来源、结果和时间范围筛选及分页。
- 调用日志默认保留 30 天，由后台任务分批清理；通过 `INVOCATIONS_*` 环境变量配置。
- 条件模型和设计器支持嵌套的 `all`、`any`、`not` 组合及类型化条件编辑。
- `/metrics` 提供 HTTP 请求和延迟、规则求值和耗时、数据库连接与日志清理指标。Nginx 未将此端点转发到公网；Kubernetes 后端 Service 为集群内服务。
- 管理端 SDK 输出由 Orval 生成；`make check-sdk` 检查生成结果与 OpenAPI 是否一致。

## 已知限制与待办

### 数据与可靠性

- [ ] 大部分实体仓储仍在进程内缓存聚合并整组同步数据库表。发布操作带事务和并发序列号保护，调用日志直接读写 PostgreSQL；其他仓储尚不支持多进程缓存一致性。当前部署限制为单个 API 副本。
- [ ] 完成生产数据库备份恢复演练，并记录恢复时间、恢复点和验证结果；补充升级失败时的处置步骤。
- [ ] 告警目前由后台 goroutine 直接投递，缺少持久化队列、有限重试、幂等和投递状态查询。

### 安全与观测

- [ ] 为项目凭据增加最后使用时间和凭据级审计；公网开放求值 API 前增加按项目或凭据限流。
- [ ] 编写 JWT 签名密钥轮换及紧急撤销操作流程；只有跨服务复用 Token 或扩展授权范围时再引入 `aud` 校验。
- [ ] 扩大认证、组织/项目权限隔离、发布并发和通知投递的自动化测试覆盖，并纳入合并保护。
- [ ] 为 Prometheus 指标补充部署侧抓取配置和基础告警规则；指标端点继续保持在受控网络范围内。

### 规则与性能

- [ ] 版本历史增加字段级差异视图；当前版本查看以快照并排呈现。
- [ ] 完善条件编辑器按事实类型限制操作符、节点级错误定位及复杂组合的交互测试。
- [ ] 运行固定数据集的规则求值和端到端压测，记录资源配置、并发、吞吐、p50/p95/p99 与错误率；根据结果决定是否需要索引、缓存或热更新。
