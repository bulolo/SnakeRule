# SnakeRule 开发路线图

本文按当前代码维护状态；“已完成”只表示基础版本存在对应能力，不代表已经满足生产级多租户或高可用要求。当前版本：`v0.1.0`。

## 已完成：管理工作台与规则求值基础版

- [x] Go HTTP API、健康检查、就绪检查和版本接口。
- [x] 配置管理员登录、会话查询/退出、HttpOnly Cookie 与会话过期。
- [x] 默认组织初始化，组织创建、更新、删除和会话级切换。
- [x] 组织内项目创建、更新、删除和会话级切换；新组织不自动创建项目。
- [x] 项目范围的规则集列表、创建、读取、更新和删除。
- [x] 电商订单演示项目及其订单风控规则。
- [x] 项目 API Key 创建、摘要存储、撤销和求值鉴权。
- [x] 系统告警渠道与项目告警策略，并在规则命中时通知。
- [x] 规则集/规则基础校验及优先级排序。
- [x] 嵌套 `all`、`any`、`not` 条件树和基础事实操作符。
- [x] 已保存规则集求值和未保存草稿试运行。
- [x] React 管理端概览、规则管理、画布/JSON 编辑和决策结果查看。
- [x] 平台授权状态展示、授权文件上传/替换/清除，以及 Pulse Agent 校验集成。
- [x] 开发与生产 Docker Compose、Nginx 统一入口和 VitePress 文档站点。
- [x] OpenAPI 契约及管理端 TypeScript SDK 生成命令。

## 下一阶段：数据库迁移和安全边界

- [x] 接入 PostgreSQL 实体表持久化与 Goose 版本迁移，开发、生产 Compose 与 Helm 均包含数据库，并在首次启动时应用初始 schema。
- [ ] 明确生产环境备份/恢复、并发更新、迁移回滚和文件损坏恢复策略。
- [ ] 增加独立用户、角色和资源授权；替换单一管理员凭据模型。
- [ ] 完善 API Key 生命周期：增加过期、轮换、最后使用时间和管理审计。
- [ ] 明确现有项目 JWT 的签名密钥轮换、有效期、撤销及 issuer/audience 校验策略；只有接入外部身份提供方或 OAuth/OIDC 时再扩展相应流程。
- [ ] 为外部调用增加按凭据/组织的限流、审计和密钥泄露响应流程。
- [ ] 确认公网部署的 TLS、密钥轮换和会话撤销流程。

## 后续：规则生命周期和运行观测

- [ ] 规则集发布、不可变版本快照、回滚与变更审计。
- [ ] 决策历史、可追溯条件结果、查询和保留策略。
- [ ] 规则规模增长后的索引、缓存与热更新方案，并提供基准数据。
- [ ] 完善条件画布中的组合编辑、操作符提示和输入校验。
- [ ] 通过 API/管理端展示真实运行指标；在完成数据采集前不显示推测性的调用量或命中率。

## 后续：受控动作执行和集成

- [ ] 定义规则动作执行模型、超时、重试、幂等和失败语义；当前动作仍不执行。
- [ ] 评估 Jev 或其他外部 AI 服务；明确供应方、数据出境、成本、超时和降级策略后再接入。

- [ ] 在规则管理/求值服务需要独立扩缩容时，再评估拆分计算节点和消息/缓存基础设施。
