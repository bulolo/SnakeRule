# 规则生命周期与运行观测

本文概述规则发布、调用追溯和运行指标的现有实现，以及仍需完善的事项。

## 规则发布

规则集草稿保存在 `rulesets`；发布时在 PostgreSQL 事务中创建 `ruleset_versions` 快照，并更新当前发布版本。版本快照包含规则定义、内容摘要、发布者、时间和说明。发布并发通过事务级 advisory lock 分配递增版本号。回滚会复制旧快照并创建新版本，不会覆盖历史记录。运行 API 读取已发布快照，设计器模拟可使用未发布草稿。

管理端提供发布、版本历史、快照并排查看和回滚流程。字段级差异视图、发布事件独立审计表和跨 API 副本缓存一致性仍未实现。当前仅支持单 API 副本。

## 调用追溯与保留

调用记录存入 PostgreSQL，关联请求 ID、项目、规则集、实际发布版本、来源、结果、命中规则、耗时和脱敏后的请求/响应预览。管理端支持按规则集、请求 ID、来源、结果和时间范围分页筛选，并在详情中查看请求、响应和命中信息。

默认保留 30 天，后台按批次删除过期记录。通过 `INVOCATIONS_RETENTION_DAYS`、`INVOCATIONS_CLEANUP_INTERVAL_SECONDS` 和 `INVOCATIONS_CLEANUP_BATCH_SIZE` 配置。清理状态通过 `/metrics` 暴露。该清理策略只针对调用日志，不清除发布快照。

## 条件画布

规则条件模型和编辑器支持嵌套的 `all`、`any`、`not`。操作符和输入控件按当前值类型选择；按事实 schema 自动限定操作符、在具体节点定位错误以及完整的复杂组合交互测试仍待完善。

## 服务指标

`/metrics` 暴露有界路由分组的 HTTP 请求计数与延迟直方图、规则求值结果与延迟、数据库连接池状态和日志清理状态。管理端调用概览仍以持久化调用日志为数据源，不以进程指标推算服务指标。Nginx 不代理 `/metrics`，Helm 后端 Service 保持集群内可达；抓取配置和告警规则需要由部署环境补充。

指标不使用用户输入、项目 ID、规则集 ID、API Key 或请求 ID 作为标签。Prometheus 可从直方图计算分位数；应用本身不保存 p95/p99 时序数据。

## 后续工作

1. 将非日志实体仓储改为数据库主导的细粒度查询和更新，或提供可靠的跨进程并发控制；完成冲突测试后再开放多个 API 副本。
2. 完成 PostgreSQL 备份恢复演练、升级失败处置和发布前迁移检查。
3. 为告警投递增加持久化队列、有限重试、幂等和投递状态查询。
4. 为项目凭据增加最近使用时间和审计；在公网开放求值 API 前增加限流。
5. 补齐条件编辑器复杂交互测试、版本字段级差异视图和基于固定负载的性能基线报告。
6. 在部署侧配置 Prometheus 抓取及基础告警，并维持指标端点的网络访问边界。
